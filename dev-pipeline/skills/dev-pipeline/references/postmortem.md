# 부검 (10단계)

문제가 발생했을 때만 실행한다.

## 부검 에이전트
새 `general-purpose` 에이전트를 띄운다. 지시에 명시할 것:
- **입력:** (a) 문제 설명과 재현 절차(사용자가 준 사실, 이슈가 있으면 그 내용), (b) 문제 커밋과, 찾을 수 있다면 그 커밋을 만든 세션의 대화 기록, (c) 관련 코드와 스펙·계획 문서.
- **산출:** 문제 지점(`파일:라인`), 근본 원인, 파이프라인의 어느 단계(인터뷰 누락? 스펙 결함? 지시서 오류? 테스트 설계 구멍(스펙 항목 누락·약화·mock 경계 오판)? 구현 실수? 검증 구멍?)에서 새어 나갔는지의 역추적, 재발 방지책.
- **사실은 입력 그대로, 해석은 에이전트가.** 무엇이·언제·커밋·영향받은 코드는 입력에서 받은 그대로 쓰고 지어내지 않는다. 원인 해석이 추측이면 추측이라고 표시한다.
- **절대 규칙: 소스 코드를 한 줄도 수정하지 않는다.** 쓰는 파일은 부검 보고서뿐이다. 수정안은 제안만 한다.

읽기 전용은 지시로만 보장되므로, 완료 후 `git status`로 보고서 외 파일이 바뀌지 않았는지 확인한다.

## 보고서
`docs/reports/postmortem-YYYY-MM-DD-<slug>.md`에 [부검 보고서 템플릿](../assets/postmortem-report-template.md) 형식으로 저장한다. 프로젝트에 기존 보고서 디렉토리가 있으면 그 관례를 따른다. 기준이 된 스펙·계획 문서를 참조로 남긴다.

## 수정과 재검증
코드 수정은 보고서를 근거로 **원 구현 에이전트**(6단계에서 해당 영역을 맡은 에이전트)에 재위임하고, 7단계 검증을 다시 통과시킨다. 부검이 테스트 설계 구멍을 지목했다면 `seongho:test-design`을 update로 다시 실행해 골격부터 보강한다.

## 스킬·에이전트 개선
부검이 재발 방지책으로 `.claude/skills/*`, `.claude/agents/*`, 프로젝트 지침 파일의 결함(빠진 규칙, 모호한 지시)을 지목하면, 오케스트레이터가 사용자 승인을 받아 해당 정의를 직접 개선한다. 플러그인으로 설치된 정의는 설치본(캐시)이 아니라 원본 저장소의 파일을 고쳐야 반영된다. 파이프라인이 스스로 학습하는 지점이다.

## 최종 검토와 커밋
수정이 있었다면 사용자에게 (a) 수정 diff, (b) 재검증 결과, (c) 부검 보고서 경로를 제시한다. 사용자의 최종 확인 후 [커밋 규칙](commit-and-revert.md)대로 커밋한다. 해결된 이슈가 있으면 커밋 메시지로 연결한다.
