# 역할

커밋 메시지를 짧고 정확하게 쓰고, 파이프라인 커밋에는 **현재 세션의 `Session` 트레일러**를 스크립트로 삽입·검증해 커밋한다. 이 스킬은 stage와 push를 하지 않는다.

# 메시지 규칙

형식, 언어, 이슈 번호 표기는 **프로젝트의 지침 파일(`CLAUDE.md`, 기여 가이드)과 `git log`의 관례**를 따른다. 관례가 없으면 Conventional Commits(`<type>(<scope>): <요약>`)를 쓴다.

- 변경 목록보다 **변경 이유**를 남긴다. 제목으로 충분하면 본문을 생략한다.
- 실제로 연결된 이슈가 있을 때만 번호를 적는다. 번호를 만들어 넣지 않는다.
- 호환성 변경, 보안 수정, 데이터 마이그레이션, revert는 이유와 영향을 본문에 남긴다.
- 독립적인 변경이 섞여 있으면 호출자에게 커밋 분할을 제안한다.
- "이 커밋은…", "요청하신 대로…" 같은 도입 문구와 diff에서 바로 보이는 내용의 반복을 쓰지 않는다.

# 추적 필드: Session

- 형식: `Session: claude:<세션 ID>`. 파이프라인 커밋의 필수 필드다. 설명 본문이 없어도 남긴다.
- 변경을 작성한 세션과 커밋하는 세션이 다르면, 확인된 관련 세션마다 이 필드를 반복한다. 커밋 세션만으로 이전 작성 세션을 대신하지 않는다.
- 출처를 확인할 수 없는 ID는 만들어 넣지 않는다. 호출자에게 이유를 알린다.
- 추적은 **커밋 → 세션 ID → 보존된 세션 기록 → 판단 근거**로 이어진다. 세션 기록을 열 수 없으면 추적이 완전하다고 표시하지 않는다. 사용자 결정, 참고 자료, 관찰된 검사 결과만 근거로 쓰고 기록에 없는 사고 과정을 지어내지 않는다.

# 커밋 절차

1. 승인된 파일만 stage돼 있는지 `git status`로 확인한다.
2. 메시지를 임시 파일로 작성한다(커밋 대상 저장소 밖 또는 추적되지 않는 위치).
3. `node <이 스킬 디렉토리>/scripts/session-stamp.mjs commit <메시지 파일>`로 커밋한다. 스크립트가 현재 세션의 `Session` 트레일러를 삽입·검증한 뒤 `git commit -F`를 실행하고, 커밋된 메시지에 트레일러가 남았는지 확인한다.
4. 스크립트가 실패하면(런타임 세션 ID 없음, 값 충돌, 잘못된 Session 값) **커밋하지 않고** 사유를 사용자에게 알린다. 수동으로 ID를 적어 우회하지 않는다.

세션 ID는 플러그인의 `SessionStart` 훅이 환경 변수(`AI_SESSION_TOOL`, `AI_SESSION_ID`)로 전달한다. 훅이 동작하지 않는 환경(예: 훅 비활성화)에서는 커밋이 차단된다.

# 범위

- 이 강제는 파이프라인 커밋에만 적용한다. 일반 `git commit`은 바꾸지 않는다.
- amend, push, 상태 갱신(스펙·계획)은 호출자가 한다. 별도 JSON·DB·"마지막 세션" 파일을 만들지 않는다. 원문 세션 로그와 인증 정보는 Git에 넣지 않는다.

바로 쓸 메시지를 코드 블록으로 반환하고, 추적 누락이나 분할 제안은 메시지 밖에 짧게 덧붙인다.
