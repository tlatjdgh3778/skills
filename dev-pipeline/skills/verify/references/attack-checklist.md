# 수색 체크리스트

스펙에 해당하는 항목만 코드 경로를 따라 추적한다(실행하지 않는다). 해당하지 않으면 `해당 없음`과 이유를 쓴다. 코드만으로 판단할 수 없으면 `시도 불가`와 이유를 쓰고 필요한 실행 근거를 적는다. 모든 시도에 근거(`파일:라인`, 또는 읽기 전용 명령의 출력)를 남긴다.

## 입력
- 빈 값, 공백뿐인 값, 누락된 필드
- 경계값: 최소, 최대, 최대+1
- 잘못된 형식·타입, 알 수 없는 필드
- 크기·길이 제한을 넘는 값

## 상태와 순서
- 같은 요청 반복, 중복 입력
- 존재하지 않는 대상, 이미 처리된 대상
- 호출 순서를 바꾼 경우

## 실패와 복구
- 중간 단계 실패 시 이전 상태가 보존되는지
- 실패가 성공이나 빈 결과로 보고되지 않는지
- 오류 종류별로 구분된 응답인지

## 동시성
- 같은 대상에 대한 동시 요청에서 중복·유실·뒤섞임이 없는지

## 권한과 경계
- 스펙이 정한 권한 매트릭스 밖의 주체로 요청했을 때 거부되는지
- 권한 검사가 입력 검증보다 앞서는지(스펙이 그렇게 정했다면)
- 다른 소유자·범위의 데이터가 노출되지 않는지

## 스펙과의 일치
- 계약의 필드·타입·상태 코드가 구현과 일치하는지
- 스펙에 없는 필드·동작·화면이 추가되지 않았는지
- 비목표를 침범한 구현이 없는지

## 사용자 화면 (화면이 있는 경우)
- 로딩·오류·빈 결과가 구분되어 표시되는지
- 실패 시 입력이 보존되는지
- 성공 후 관련 화면에 반영되는지
- 새로고침·재진입에서 상태가 복원되는지
- 키보드 조작과 폼 레이블

## 테스트 근거
- 연결된 테스트가 조건을 만들고 기대 결과를 assertion으로 확인하는지
- 빈 assertion, 조건부로 무검증 통과하는 분기, skip·todo·fixme가 없는지
- 기대 결과가 약해지지 않았는지(구체 값을 확인하지 않고 존재만 확인하는 경우 등)
- 핵심 제품 동작을 mock으로 대체해 통과시키지 않았는지

## 변경 위생
- 스펙 범위 밖 파일이 변경되지 않았는지(`git diff`)
- 생성 산출물을 직접 수정하지 않았는지
