# 위임 프롬프트 형식

에이전트에게 다음 형식으로 전달한다. 지시서는 요약하지 말고 전문을 붙인다.

```
[스펙 경로]
<스펙 파일 경로>

[모드] (테스트 지시서일 때만)
살 모드 — 골격 파일 <경로>의 case 본문만 채운다. `@spec`·`@given`·`@when`·`@then` 태그와 case 서술은 바꾸지 않는다. 골자가 틀렸다고 보이면 고치지 말고 NEEDS-DECISION으로 보고한다.

[지시서]
<지시서 전문>

[규칙]
- 지시서의 수정 허용 범위 밖은 건드리지 않는다.
- 인터페이스 계약을 바꾸지 않는다. 변경이 필요하면 구현하지 말고 보고한다.
- 테스트 파일을 수정하지 않는다. 테스트가 실패하면 구현을 고친다. (테스트 지시서를 받은 에이전트는 지시서가 지정한 테스트 파일만 작성하며, 테스트를 실행하지 않는다)
- 실패를 숨기기 위한 skip·기대 결과 완화·검사 설정 변경을 하지 않는다.
- 다른 에이전트를 만들거나 위임하지 않는다.
- 스펙과 지시서에 없는 결정을 추측하지 않는다. 막히면 보고한다.

[보고]
구현 완료 후 다음만 간결하게 보고한다.
- 상태: IMPLEMENTED | BLOCKED | NEEDS-DECISION
- 수정한 파일 목록
- 지시서의 실행 명령과 그 결과
- 스펙·지시서와 달라진 점 (없으면 "없음")
- BLOCKED·NEEDS-DECISION이면 근거와 필요한 조치·결정
```
